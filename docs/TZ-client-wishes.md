# MonsterWork — Техзадание и карта восстановления

Дата: 2026-11-02 · Ревизия кода: `eafea44` (v1.4, versionCode 5)

Документ сводит правки клиента, текущее состояние кода и найденную в истории
git причину регресса. Источник правок — список замечаний клиента; источник
фактов — код в `eafea44` и история до него.

---

## 1. Суть приложения

**MonsterWork** — трекер рабочих смен для графика по циклу (4/2, 2/2, вахты).

Три сущности:

1. **Календарь** — сетка месяца: дни красятся по сменам/выходным; статистика
   (смены / часы / зарплата с ночной надбавкой).
2. **Паттерн (профиль)** — конструктор цикла, накладывается на диапазон дат
   и проставляет смены пачкой.
3. **Банки монстра** — геймификация: **1 банка = 1 час работы**, заполняются
   по ходу смены. По словам клиента — «ключевая фишка в приложении».

Стек: Kotlin + Jetpack Compose, Room (одна таблица `shifts`), одна
`ShiftViewModel` на всё приложение, ~6.7 тыс. строк.
Расчёты вынесены в чистые функции (`ShiftClock.kt`, `Premium.kt`,
`ShiftDayEditing.kt`) и покрыты JVM-тестами (92 теста) — это сделано хорошо
и переписывать не нужно.

## 2. Корневая причина «неудовлетворительного» состояния

Все правки клиента вида «верни как в прошлой версии» указывают на коммит
**`7f52463`** («feat: add monster banks and shift settings»), где банки и
старая сетка **были живыми на экране**.

Коммит **`20edb3c`** («feat: profiles, night premium window, breaks,
clear-shifts, themed buttons», +2745/−795) переписал `CalendarScreen.kt`,
`DayEditor.kt`, `CanProgress.kt` и `ShiftViewModel.kt` целиком. Вместе с
полезным (профили, ночная надбавка, перерывы, очистка смен) он **потерял
две ключевые фичи** и **изменил визуал сетки**.

### Что именно потеряно

| Фича | Где было | Где сейчас | Доказательство |
|---|---|---|---|
| `MonsterBanks` на экране | `7f52463`: `MainActivity.kt:123` — вызов под `MonthGrid` | вызова нет ни в одном файле | `git grep "MonsterBanks(" HEAD -- app/src/main` → пусто |
| Банка-награда за смену | `7f52463`: `completeShift()` в VM + кнопка «Завершить смену и получить банку» | `completeShift` удалён | `git grep "completeShift" HEAD` → пусто |
| Коллекция банок | `7f52463`: пополнялась при `completeShift` | состояние `collection`/`rewardsByShift` есть в `UiState`, но **никто не читает** | `git grep "\.collection" HEAD -- app/src/main` → пусто |
| Сплошная заливка дней | `7f52463`: `background(ShiftRed/DayOffGreen)`, `aspectRatio(1f)` | `background(...α0.16)` + рамка, `height(44.dp)` | см. §4.2 |

`CanReward.kt` (вкус, редкость, `drawCan`) цел, но **недостижим** — мёртвый код.

### Отсюда — правки клиента

Клиент не строит список пожеланий с нуля. Он **фиксирует регресс**: просит
вернуть то, что видел, плюс два действительно новых элемента (квадраты
времени, ручной ввод перерыва).

## 4. Целевой вид (то, что хочет клиент)

### 4.1 Структура главного экрана

Порядок восстановлен по `7f52463` (банки стояли под сеткой) + требования клиента:

```
Header
MonthStrip            — лента 12 месяцев + стрелки года
[BankProgressCard]    — только если смена идёт прямо сейчас
MonthGrid             — квадраты одного размера, сплошная заливка
MonsterBanks          — 1 банка = 1 час, ПОД сеткой      ← вернуть
[Legend]              — только для реально используемых цветов
TotalsCard            — статистика месяца
[Удалить смены месяца] [Удалить все смены]
```

### 4.2 Сетка дней: прошлое vs сейчас

| | Прошлая (`7f52463`) | Сейчас (`eafea44`) | Цель |
|---|---|---|---|
| Размер | `aspectRatio(1f)` — квадрат | `height(44.dp)` | квадрат, всегда одинаковый |
| Заливка | сплошная `ShiftRed`/`DayOffGreen` | `α0.16` + рамка | **сплошная** |
| Текст числа | белый на цвете | `Ink` всегда | читаемый на заливке |
| Мультисмены | нет (1 смена/день) | полоски-слоты цветов | **оставить полоски** |

Правило клиента: «квадраты всегда одного размера, меняется лишь цвет» +
«дизайн с точечками когда много разных смен оставь».

### 4.3 Банки: прошлое → цель

- Прошлая `MonsterBanks` (нетто `7f52463`): жёстко **8 банок** (`(0 until 8)`).
- Клиент: **1 час = 1 банка**, перерыв не учитывать.
- Цель: **размещение из прошлого + подсчёт из текущего кода**
  (`canCountFor` = `ceil(длительность в часах)`, уже корректен: 12 ч → 12 банок).

### 4.4 Редактор времени (новое, аналога не было)

- Было (`7f52463`): кнопки `Начало ±1ч` / `Конец ±1ч`.
- Сейчас: сплошное поле `HH:mm`.
- Цель: `[ЧЧ]` квадрат · **некликабельное** `:` · `[ММ]` квадрат.
  - каждое из ЧЧ/ММ — отдельное поле, редактируются независимо;
  - двоеточие статично, тапом не активируется.

### 4.5 Перерыв (новое)

- Было: перерыва не было.
- Сейчас: `−5` / `+5`.
- Цель: чистое поле ввода минут, без кнопок.

## 5. Предлагаемая архитектура

Три независимых слоя, чтобы правки не задевали друг друга.

### 5.1 Слой модели (чистые функции, JVM-тесты)

```
model/
  CanReward.kt      + вернуть completeShift-потребителя (см. §6, вопрос 1)
  MonsterBanks.kt   + cansForShift(shift): Int          (обёртка над canCountFor)
                    + cansProgress(shift, now): List<Float>  (заливки всех банок)
  CalendarModel.kt  + usedColors(month): Set<ColorKey>  (для контекстной легенды)
  MultiShift.kt       без изменений
```

### 5.2 Слой состояния

Плоский `UiState` (≈60 полей) разбить на три под-состояния:
`CalendarState` (месяц, сетка, легенда) · `EditorState` (день, смены, время,
перерыв) · `PatternState` (цикл, профили, превью). VM остаётся один, но
композаблы получают узкие срезы — правка одного экрана не тянет остальные.

### 5.3 Слой UI

```
CalendarScreen.kt  DayCell → сплошная заливка, aspectRatio(1f)
                   LegendRow → Legend(usedColors)   (контекстная)
                   MonsterBanks вызов               (вернуть в композицию)
DayEditor.kt       TimeField → TimeBoxes(ЧЧ : ММ)
                   BreakRow → BreakInput (поле минут)
```

### 5.4 Что НЕ трогать

`Premium.kt` (надбавка/перерыв), `ShiftClock.kt` (банки/прогресс),
`Pattern.kt` (движок цикла), DAO, тесты — они работают и покрыты тестами.
